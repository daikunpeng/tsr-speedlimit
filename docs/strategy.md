## 1. 最终目标（部署约束优先）

| 项 | 要求 |
|----|------|
| 中级目标 | **YOLOv5 级检测器** + **极小分类器**，中国场景限速标志检测与识别 |
| 板端 | 地瓜派 **RDK X5** |
| 相机 | GS130WI，约 120° 宽角，畸变大；推理图为**已去畸变** |
| 输入分辨率 | **640×352** |
| 在线帧率 | ≥ **10 Hz** |
| 离线目标 | 尽量 ≥ **60 Hz**（留出余量） |

原则：**官方生态成熟度 > 排行榜多几个点**。优先 YOLOv5n/s 及板端已验证的转换/量化路径；不默认追 YOLO8/11/Transformer，除非板端已验证可用。

训练可以在 RTX 3060 上用更大 teacher；部署只保留小模型。

## 2. 系统架构（两级，不要单模型细分类）

```
Camera Image (640×352, undistorted)
        │
        ▼
┌───────────────────┐
│ Detector (YOLOv5n/s) │  类别尽量简单：speed_limit_sign（可选 other_sign）
└─────────┬─────────┘
          │ bbox
          ▼
     crop ROI
          │
          ▼
┌───────────────────┐
│ Tiny Classifier     │  20/30/40/50/60/70/80/...
└───────────────────┘
```

原因：
- 检测只要认出「限速牌」；分类要读数字——特征需求不同。
- 远距离：能检出但易分错；近距离才易分对 → 需 object-centric + 时序，而不是把所有类别塞进一个 detect head。

板端推理还可加：
- **Tracking** → sign lifecycle
- 选最清晰几帧 → classifier → **多帧投票**
- 多数帧无牌时 classifier 几乎不跑，算力可控。

---

## 3. 核心问题：防 shortcut / 跨相机泛化

公开数据（TT100K 等）与自采（GS130WI）混训时，模型容易学：
背景、相机风格、FOV、清晰度、道路类型 → 类别，而不是「红圈 + 数字」。

策略主线：

**多域数据 → 削弱域偏差 → 强化牌面局部特征 → 模拟真实退化 → 分阶段训练 → 按域验证 → Hard Case 闭环**

优先手段（工程收益高）：
1. Detector / Classifier **解耦**
2. 全部做成 **sign-centric crop**（tight / 1.3–1.5× / 2.0× 等）
3. **Small-object degradation**（缩到 8/12/16/24/32 px 再放大）
4. Copy-Paste / background swap，打断「背景↔类别」相关
5. 按 Camera / Road / Trip / Physical Sign 做 **OOD split**，禁止视频连续帧随机划分

核心 KPI（比单一 mAP 更重要）：
- **sign 像素尺寸 → 分类准确率曲线**
- 按 domain 的 Recall / Classification 矩阵
- Background-swap 时 P(class) 是否稳定

## 4. 数据阶段顺序（先数据，后定模型细节）

当前阶段：TT100K 已完成两级冒烟训练与量化模拟；GS130WI 自采测试集已落地，
用于评估目标域差异。自采标签数量少、按 trip 分布不均，部分非限速牌漏标；
**暂不将这些帧直接作为完整监督训练集**。

推荐顺序：

1. 收集 / 下载（现：TT100K）
2. 统一标签体系（保留原始 label 可追溯）
3. 每条样本带 **domain metadata**（source、camera、resolution、trip…）
4. 生成 sign crop
5. **数据体检**（类别数、尺寸分布、长尾、重复帧…）
6. 再定训练超参与增强强度

第一版 unified label（示例）：

- 检测：`speed_limit_sign`（pl* 最高限速 + il* 最低限速；pm* 限重已移出，见 AGENTS.md 语义修正）
- 分类：`speed_limit_20` / `30` / `40` / …（由 TT100K 的 `pl*` / `il*` 映射；pl/il 分组）

TT100K 过滤范围见 `AGENTS.md`：正类 `pl*`（最高限速）+ `il*`（最低限速）；`pm*`（限重）移入 `data/TT100K_weight_pm/` 留档。

增强（数据体检后再加强）：small-object degradation、blur、JPEG/ISP、畸变随机化、domain-balanced sampling 等。**现阶段不要一上来堆大量 augmentation。**

## 8. GS130WI 目标域优化（2026-09-23 与用户确认）

**业务目标**：允许远处暂时漏检；在路牌接近车辆、完整可见且有足够像素时，
输出稳定、正确的限速值。仍须保留 640×352、在线 ≥10 Hz 和两级架构。
TT100K 测试集逐帧指标与自采尺寸分桶指标继续报告，但不能代替末段事件指标。

**初始事件验收定义**：按 trip 内同一实体路牌的连续 GT 框组成事件；
在接近阶段（暂以 GT 短边达到最大值的帧为终点）寻找短边 ≥24px 的
连续 5 个采集帧，取最后一个完整窗口；其中至少 3 帧检测匹配且分类正确，
并且该事件在可验阶段不出现连续 5 帧中 ≥3 帧的同一错误稳定值。
报告须同时给出：总事件数、具备完整 5 帧窗口的事件数、可验事件通过率、
未具备窗口的原因、误报及逐帧尺寸/分类明细；不可把无足够窗口的事件计为通过。
窗口为初始研发口径，若业务需要其他像素/时间阈值，先与用户确认再改。
真实路牌可能在结束前出画或被遮挡，不能机械地把整个 trip 的最后 5 帧当作末段。

**数据边界**：现有 6 trip / 982 帧约 9 次主要路牌经过（自动分组须人工复核），
不足以证明跨 trip 泛化；现有 self 可作开发评估，未来新的独立 trip 用于验收。
部分非限速牌漏标，FP 须抽样目检；严禁将未核实的空标签帧当完全准确负样本训练。

**实验顺序（逐项对照）**：
1. 既有模型的输入预处理小实验：原图基线 vs 温和锐化/局部对比度；
   只在自采原始 640×352 输入上实验，观察事件稳定性、误报与耗时。
   去畸变前图像不可得，ISP/降噪/锐化参数暂不可调；不开展无法验证的上游对比。
   **首轮已完成**（`reports/preproc_pilot.md`）：温和锐化、LAB 亮度 CLAHE
   均未提高末段事件通过数，且逐帧 E2E 低于原图；不默认部署这两种处理。
2. 主线仍以 TT100K train 为训练源。在训练时缩放到 @640/部署尺度后，
   做**轻度、部分概率**的局部方向性模糊、拉伸重采样、压缩等成像退化；
   保留清晰样本，并与未增广权重成对比较 TT100K 回归与 GS130WI 事件表现。
   源图不离线 resize；几何变换必须同步变换标注框。不能假设锐化能恢复丢失的数字。
   **首轮单因素完整训练已完成**（`reports/detector_smear_ablation.md`）：
   val mAP50 略升，但 TT100K test E2E 84.2→81.0%、GS130WI E2E 9.7→10.3%，
   严格可验事件 2/3→1/3；不将该权重替换为默认 smoke1。
 3. 若单独退化增广收益不足，再独立评估 640×352 画幅/路牌靠近上缘及侧边的
    空间分布增强；之后才考虑分类器小尺寸 crop 增广与 tracking/多帧投票。
    **位置/画幅单因素已完成**（`reports/detector_crop_ablation.md`，tt_crop1）：
    self det 24–32px @0.5 +16.7pp、总体 +4.3pp、无定位 −13，是 self 域最好的
    检测器；但新召回的暗红牌被 cls v2 大量判 `other`，E2E/事件未随之上升。
    级联未超 smoke1，暂不替换默认权重；tt_crop1 记为 self 域检测器候选。
    **瓶颈确认移到分类器**：下一步优先做 cls 牌面局部颜色/曝光增广（小成本），
    之后再议检测器侧颜色增广与是否叠加位置裁切（均须另行确认）。
4. 降阈值不能替代域适应：smoke1 的 self GT 检测分数中位约 0.00165，部分 GT
   连 IoU≥0.5 定位都没有，低阈值会引入大量远处 FP。不过冻结 smoke1
   在 conf0.25 的开发集可验事件由 2/3→3/3；13 个名义速度 FP 均 <12px，
   可讨论发布前尺寸/时序门控。此结果仅有 3 个可验事件，不是独立验收。
   若 TT100K-only 仍失败，
   再讨论可核实的少量目标域标注或其他域适应方式，并按实体牌/trip 隔离训练与验证。

全量/长时间训练须先征得用户确认；改变训练数据边界前先更新本文件与 AGENTS.md。
用户已批准**两次 TT100K-only 检测器全量训练对照**（授权均已在当次使用完毕）：
1. 涂抹/局部重采样（tt_smear1）：与 smoke1 同参，唯一新增在线缩放后局部
   压缩→重采样（坐标复位、标注框不动；按概率保留清晰样本）；
2. 位置/画幅裁切（tt_crop1，2026-09-24 用户建议并批准）：训练期在线
   640×352 裁窗，50% 概率把 GT 牌置于窗口顶部带，标注同步平移/裁剪/删除。
训练验证集不做这些增强；训练后一律在 TT100K test 和 self 开发集按本节指标对照。
**两次授权均已使用**；任何后续全量训练（含检测器侧颜色增广）须重新确认。

### 8.1 冻结权重诊断结论（2026-09-24，`reports/frozen_diag.md`）

用冻结 smoke1 + cls v2 在 self 上做只读诊断（GT crop、颜色启发式、位置统计）：

- **检测器主因是牌面色彩/渲染偏移**：`_4`（过曝发白，核心亮度 ~192–228）、
  `_9`（暗，红圈红度 ~2–3）几乎无定位（无定位框 23/30、34/70）；
  `_3` 外观接近 TT100K（红度 33–85、亮白底）则 det conf 0.84–0.92。
  24–48px 上缘牌 conf P50 0.37 vs 中部 0.70，位置有影响但与颜色高度共变。
- **分类器同样受色彩/牌面规格影响**：暗红 pl40（`_7`）与 pl20（`_5`）GT crop
  大量判 `other`（24–48px 正确仅 25/34）；且处于决策边界——同框 1px 行偏移即
  `other 0.72→pl40 0.95` 翻转。检测框 vs GT 框的微小差异即可改变输出。
- 推论：即使检测召回解决，分类器在当前自采外观下也难以稳定读值；
  **牌面局部颜色/曝光增广（检测器+分类器两侧）是比涂抹更关键的候选因素**，
  需另行申请训练授权。位置裁切实验照原计划进行，作为位置/画幅单因素对照。

### 8.2 位置/画幅裁切结论（2026-09-24，`reports/detector_crop_ablation.md`）

- tt_crop1 是 self 域最好的检测器（24–32px @0.5 60%、总体 16.2%、无定位 55），
  但级联被分类器卡住：cls v2 把新召回的暗红牌判 `other`（det TP 上 cls 56.7%），
  E2E/事件未超 smoke1。**暂不替换默认权重**，tt_crop1 记为 self 域检测器候选。
- 下一步优先级（均须用户确认）：cls v3 牌面局部颜色/曝光增广（分钟级小训练）
  → 视结果再议检测器侧颜色增广全量训练及是否与位置裁切叠加。

### 8.3 分类器颜色/曝光增广结论（2026-09-24，`reports/cls_v3_cascade.md`）

- cls v3（v2 同参 + 训练期牌面颜色/曝光增强概率 0.5）把 self GT-crop 分类
  112→159/185，暗红 `_7`、`_5` pl20 的 other 边界翻转基本消除。
- **tt_crop1 + v3**：self E2E 9.7→15.1%、事件 3/3、24–32px E2E 53.3%；
  TT100K smoke1+v3 84.4%（不降）。**建议 tt_crop1+v3 为目标域默认组合候选**，
  待用户确认替换默认权重。
- 剩余瓶颈回到检测器：self 55/185 无定位（`_9`/`_4` 暗/过曝小牌）→
  检测器侧牌面颜色/曝光增广全量训练为下一候选（另行授权）。

### 8.4 检测器侧颜色/曝光增广结论（2026-09-24，`reports/detector_cropcolor_ablation.md`）

- A 步漏检帧诊断：大牌漏检主因是**色彩**（漏检组红度 P50 6、亮度 90 vs 检出
  30/184），非尺寸/锐度；另有 ~3 帧非颜色因素（`_3` 帧67 等）需目检。
- B 步 `tt_cropcolor1`（crop352 配方 + PlateColorAug 牌面局部颜色增广）：
  **cropcolor1 + cls v3** self det@0.5 11.9→37.3%、无定位 68→11、E2E 9.7→34.1%、
  事件 3/3、近距曾读对 8/9——目标域最大单一杠杆。
- 代价：TT100K E2E 84.2→75.5%（干净 <8px/≥48px 牌置信下降；12–28px 带仍 93.4%
  recall）。默认组合候选 **tt_cropcolor1 + cls v3**。
- 可选后续（另行授权）：降增广概率/收窄强度，或仅对 12–48px 目标带增广，
  以找回 TT100K 干净牌；仍需新 trip 独立验收。

### 8.5 尺度敏感性发现 + 暂停项 TODO（2026-09-24）

- **验收标准已修正（用户 2026-09-24）**：某目标生命周期内**存在连续 3 帧
  检出且分类正确**即通过（取消 ≥24px 与“末段 5 帧窗口”）；检出=det conf≥0.5，
  报告附 conf≥0.25 次要口径；连续 ≥3 同错值为硬性不通过；生命周期 <3 帧单列
  “不可验”、不计入通过率分母。理由：像素阈值是数据/几何限制，短距离接近窗口，
  且 <20px 能检出是有价值的能力。新标准下 cropcolor1+v3 **7/10** 通过
  （`_1`、`_4` 差 1 帧；`_7` 生命周期仅 1 帧不可验）。
- **`_1` pl60 漏检成因判定**（多尺度推理 `scripts/diag_scale_sweep.py` + 用户目检）：
  **非颜色/模糊/遮挡/杂乱，而是输入尺度敏感性（混叠）**。冻结 tt_cropcolor1 对
  `_1` 每帧都定位（IoU 0.89–0.97），但 15–20px 区间（帧 46–50）conf 塌陷到
  0.004–0.28；同一帧换输入尺度即回升（帧 46：1.0×=0.034→1.5×=0.570；
  帧 48：1.0×=0.004→0.5×=0.338），≥21.6px 的帧 51–53 则跨尺度稳健（0.51–0.87）。
  即：同一物理外观在原生 640 输入下落入检测头网格的“坏尺寸带”，换尺度即恢复。
- **实验 A（PlateColorAug 尺寸门控 12–48px）暂停**：它治的是暗/过曝牌召回
  （`_4`/`_9` 类），预计不解决尺度窄带问题，留待恢复。
